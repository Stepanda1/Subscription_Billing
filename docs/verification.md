## Локальный мини-бенчмарк

```sh
python scripts/load.py --requests 2000 --concurrency 40
```

Один API и один worker. Docker Desktop Linux: 12 vCPU, около 7.63 GiB RAM;
клиент Python 3.13 на Windows 11. Runtime .NET 8.0.31, PostgreSQL 16 и RabbitMQ 4.
Каждый POST использовал новый UUID-ключ, один общий пользователь и тариф basic.
Клиент подключался к `127.0.0.1:8080`, создавал новое HTTP-соединение на запрос.
API уже работал после smoke-проверки; отдельного формального warmup не было.

| Метрика | Результат |
|---|---:|
| Запросы / параллелизм | 2000 / 40 |
| HTTP 202 | 2000 |
| Время записи | 4.839 с |
| Принятые запросы в секунду | 413.27 |
| p50 / p95 HTTP | 90.69 / 152.23 мс |
| Активированные подписки после записи | 2000 |

Это один короткий локальный прогон. RPS измеряет принятие в БД/outbox, а не
завершение активации; после записи скрипт отдельно дождался всех активаций.
Он включает задержки клиента, сети и БД. Эти числа не являются production SLO,
долгим soak test или максимальной ёмкостью сервиса.

При первом запуске клиент использовал `localhost`: задержки подключения
на этой Windows-системе искажали результат. Прямой IPv4 убрал эту задержку;
скрипт использует его по умолчанию. На другой машине результаты будут отличаться.

Тесты и smoke выполняются также в `.github/workflows/ci.yml` для push и pull request.
Локальный результат и статус GitHub Actions нужно рассматривать отдельно.
